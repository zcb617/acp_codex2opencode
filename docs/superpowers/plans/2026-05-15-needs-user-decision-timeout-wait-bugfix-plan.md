# NEEDS_USER_DECISION 超时等待自推进 BUG 修改计划

## 1. Bug 与设计来源

- Bug 名称：`NEEDS_USER_DECISION` 提示后主会话同轮自推进。
- 设计文档：`docs/superpowers/specs/2026-05-15-needs-user-decision-timeout-wait-bugfix-design.md`
- 当前失败链路：实施阶段无进展 -> 进入用户决策 -> 主会话同轮倒计时并默认继续。
- 本计划目标：保留 60 秒默认继续能力，同时恢复“先停住等待用户输入”的业务交互。
- 本计划不处理：模型选择、设计/计划审批、交付整改主流程改造。

## 3. 实施任务拆分

### Task 01: Bridge 状态机增加决策等待窗口与自动默认继续触发

**业务目标：**
让插件在 `NEEDS_USER_DECISION` 后先等待用户，超时后由状态机推进默认继续，而非主会话当前轮自推进。

**对应设计目标：**
设计文档 5.1、6.1、6.3。

**修改范围：**
`src/session/bridge-service.ts`

**实施步骤：**
1. 为工作流状态增加决策等待窗口字段与自动默认继续时间字段。
2. 在进入 `NEEDS_USER_DECISION` 时建立等待窗口，并纳入快照持久化/恢复。
3. 在后续 `status` 跟进中，当超时且允许默认继续时自动执行等价 `continue_wait(timeout_default)` 的状态迁移。
4. 保持现有计数上限、清零规则与错误路径。

**自动化验证：**
UT-01、UT-02、UT-04。

**交付测试影响：**
影响实施阶段无进展决策交互。

**完成标准：**
状态机支持“先停住，再超时默认继续”，且计数逻辑不回归。

### Task 02: 返回策略字段与用户可见语义调整

**业务目标：**
让用户可见提示体现“当前停住等待”，避免引导主会话同轮执行阻塞倒计时。

**对应设计目标：**
设计文档 5.1、6.2。

**修改范围：**
`src/session/bridge-service.ts`

**实施步骤：**
1. 更新 `NEEDS_USER_DECISION` 的 `user_message` 与 `next_business_action`。
2. 在 `user_decision_policy` 中补充决策窗口截止时间等辅助字段。
3. 保持 `decision_source` 协议兼容。

**自动化验证：**
UT-03。

**交付测试影响：**
用户看到的等待/默认继续说明更新。

**完成标准：**
业务提示不再要求同轮倒计时阻塞执行。

### Task 03: Team Delegate Skill 规则修订

**业务目标：**
让主会话执行规则与状态机行为一致，禁止同轮 `sleep` 自推进。

**对应设计目标：**
设计文档 6.4。

**修改范围：**
`skills/team-delegate/SKILL.md`、`tests/delivery/team-delegate-skill.delivery.test.ts`

**实施步骤：**
1. 删除“同一轮必须等待并默认继续”的强制描述。
2. 改为“先提示并停住，默认继续由后续跟进周期触发”。
3. 明确禁止用 `Start-Sleep` 等阻塞命令模拟倒计时。
4. 同步更新 delivery 测试断言文本。

**自动化验证：**
UT-05（delivery 文档断言）。

**交付测试影响：**
主会话不再出现“自己往下走”的交互。

**完成标准：**
skill 规则与状态机一致且覆盖新语义。

### Task 04: 工作流键路径归一化与旧键迁移

**业务目标：**
避免 `D:/...` 与 `D:\\...` 导致同一任务恢复失败，消除假性 `WORKFLOW_NOT_FOUND`。

**对应设计目标：**
设计文档 11.3。

**修改范围：**
`src/session/bridge-service.ts`

**实施步骤：**
1. `workflow_key` 统一改为基于归一化路径生成。
2. `loadWorkflowState` 增加按身份（归一化 workspace + session_alias）回退查找，并迁移旧 key。
3. `findWorkflowByTaskId`、过期清理按归一化路径匹配。
4. 清理逻辑同时删除旧 key 与归一化 key 的内存映射，避免残留。

**自动化验证：**
UT-06。

**交付测试影响：**
恢复链路对路径写法不再敏感。

**完成标准：**
`D:/...` 与 `D:\\...` 两种路径写法均可命中同一在途任务。

## 6. 真实业务交付测试计划

### DT-01 决策提示后主会话停住

**业务目标：**
进入用户决策后，主会话不应同轮自推进。

**真实环境：**
本机 Codex CLI + 本地安装插件。

**真实入口：**
自然语言触发团队委派实施任务并持续跟进。

**用户语言：**
```text
过程中有进展就告诉我，没动静太久再问我是否接手。
```

**操作步骤：**
1. 触发实施并等待进入 `NEEDS_USER_DECISION`。
2. 不输入任何选择，观察当前轮主会话行为。

**期望用户可见结果：**
出现二选一后主会话停住，不出现同轮 `Start-Sleep` 或自动继续提示。

### DT-02 超时默认继续可用

**业务目标：**
无人选择 60 秒后仍可按默认继续等待。

**操作步骤：**
1. 在决策提示后保持无输入超过 60 秒。
2. 触发后续跟进周期（例如再次询问进展或由系统下一轮跟进）。

**期望用户可见结果：**
系统按默认继续等待，进入新跟进周期。

### DT-03 用户明确选择优先

**业务目标：**
用户在超时前明确选择时，系统按用户选择执行，不走默认动作。

**操作步骤：**
1. 进入决策提示后，60 秒内选择继续等待或主会话接手。

**期望用户可见结果：**
系统执行用户选择，并更新后续阶段。
